# Apple 中国官网取货结账预演

这是一段独立的浏览器脚本，使用真实 Apple 中国官网页面。默认方案是两台黑色 256GB iPhone 17、北京门店自取、个人电子发票、微信支付。它会在订单检查页停下；代码中没有点击“立即下单”或付款的操作。

## 首次使用

在本目录运行：

```sh
npm install
npm run login
```

`login` 会打开**专用 Chrome 窗口**。请在窗口里自行完成 Apple 登录及双重认证，回到终端按回车。脚本会重新打开账户主页，确认专用窗口的登录状态真的已保存。登录资料只留在仓库外层已忽略的 `.data/checkout-rehearsal/chrome-profile/`，不复制现有 Chrome 的密码或会话。

本机的 `.data/checkout-rehearsal/secrets.json` 已配置证件号码后四位；文件权限为仅当前用户可读。脚本不会把它、姓名、邮箱、手机号、Cookie 或支付资料写进计时日志，也不把它们放进 Git 跟踪文件。若在另一台电脑运行，需自行创建该文件：`{"idLast4":"你的后四位"}` 并设置权限 `0600`。

## 运行

```sh
npm run run
```

脚本先要求空购物袋，然后在官网逐一选择颜色、容量、无折抵、无 AppleCare+，加入两台设备。容量不同会形成两条商品，同容量会在购物袋中设置数量 2。它核对机型、两台数量和预期总价，选取 `plan.json` 中第一个明确可取货的门店，填写证件后四位，选个人电子发票和付款方式，再核对最终页面。完成后 Chrome 保持打开，按回车关闭。

如果购物袋已经由你备好且与方案完全一致，可用：

```sh
npm run run -- --resume-bag
```

## 开售引导页

Apple 在预购开始前可能显示“我们马上回来”等等待页；到了公布的时间后，等待页也可能继续显示。页面返回 HTTP 200 并不代表购买入口已经开放。脚本会检查目标商品或购物袋的实际内容；只看见引导页时不会继续点选。

准备在正式开售附近等待时运行：

```sh
npm run run -- --wait-for-open
```

脚本每隔约 5 秒检查一次入口，每个入口最多等待 20 分钟；若页面自己更新，会直接继续。可用 `--poll-ms=5000` 调整间隔（范围 3000–30000 毫秒）。遇到 HTTP 541、登录页或无法识别的页面会停止，不会快速连续刷新。此功能无法保证 Apple 在公布时刻放行，也无法绕过网站限流。

如果 Apple 为目标机型提供预先保存购物袋，且袋内已是方案规定的两台商品，可同时使用 `--resume-bag --wait-for-open`，从购物袋入口等待。运行前仍需把 `plan.json` 改成目标机型与实际价格。Apple 当前公布的 iPhone Duo 预购时间为北京时间 2026 年 10 月 16 日 20:00，但正式运行前应重新核对官网公告。

`plan.json` 用于调整机型官网选购网址、颜色、两台容量、北京门店顺序及支付宝或微信支付。换机型或容量时，同时按官网现价更新 `expectedTotalCny` 和 `maxTotalCny`。iPhone Duo 的选购页和结账行为仍需在正式预购时重新验证，不能直接沿用替身机型的成功结果。

`--exit-on-review` 在检查页验证完成后关闭浏览器，适合正式计时；默认保留页面供人工核对。每一步耗时记录在 `.data/checkout-rehearsal/runs/`，只含阶段、路径、门店、付款选项与金额，不含个人信息。

## 停止条件

- Apple 返回 HTTP 541 或非等待页的页面错误时立即停止，不自动重试。
- 未启用 `--wait-for-open` 时遇到开售引导页会明确停止；启用后超过 20 分钟仍未开放也会停止。
- 购物袋已有其他商品、机型/容量/颜色/数量/价格不符、没有明确可取货门店时停止。
- 登录失效、联系人缺少姓名、取货表单需要额外验证或付款方式不可用时，保留浏览器供人工处理。
- 订单检查页数量、发票、付款和总价不符时停止；始终不提交订单。

运行 `npm run check` 和 `npm test` 可检查脚本语法及关键保护规则。Apple 页面可能改变，需要在实际抢购前用在售替身机型再次走通，并重新计时。
